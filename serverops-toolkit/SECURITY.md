# 보안 및 운영 주의사항

ServerOps v0.3의 서버 진단 기능은 **조회·진단 중심**으로 설계되어 있습니다. 서비스 재시작/설정 변경 같은 쓰기 작업은 아직 기본 기능에 포함하지 않습니다.

## SSH 인증정보

- `servers.json`에 SSH 비밀번호를 저장하지 않습니다.
- SSH Key 인증을 우선합니다.
- `key_file`에는 개인키의 경로만 저장하고 개인키 파일 자체를 Git 저장소에 올리지 마세요.
- 기본 `host_key_policy`는 `strict`입니다. 처음 보는 서버의 host key를 자동 신뢰하지 않습니다.
- `accept-new`는 신규 key만 등록하고 변경된 key는 거부하지만, 사내 정책에 따라 `strict`를 유지하는 것을 권장합니다.
- Jump Host 사용 시에도 최종 서버/Jump Host의 `known_hosts` 검증 정책을 확인하세요.

## SFTP

- SFTP는 SSH 전송 채널을 사용합니다.
- `-C` 압축은 전송량 최적화이며 무결성 검증 자체가 아닙니다.
- ServerOps는 가능하면 전송 전후 SHA-256을 비교합니다.
- 원격 서버에 `sha256sum`/`shasum`이 없으면 검증을 생략했다고 명시합니다.
- ZIP 파일에 기밀 설정/로그가 포함될 수 있으므로 임시 파일과 전송 대상 경로의 접근 권한을 확인하세요.

## DB 인증정보

- DB 비밀번호를 `serverops.json`에 저장하지 마세요.
- MariaDB 점검은 `~/.my.cnf`, Unix Socket 인증 등 기존 보안 인증 방식을 이용하는 것을 권장합니다.

## 리포트/감사 로그

- `~/.serverops/audit.jsonl`에는 원격 점검 시각/대상/결과가 기록될 수 있습니다.
- 생성 리포트와 감사 로그에는 호스트명, IP, 사용자명, 내부 경로, 로그 일부 등 운영 정보가 포함될 수 있습니다.
- 외부 공유 전 민감정보를 제거하세요.

## 운영 서버 적용

가능하면 테스트 서버에서 먼저 검증하세요. 배포판/버전/최소 설치 여부에 따라 명령이 없거나 출력 형식이 다를 수 있습니다.

향후 쓰기 기능에는 최소한 다음 안전장치를 적용할 예정입니다.

- 실행 전 사용자 확인
- 변경 전 설정 백업
- Allowlist
- 변경 이력/감사 로그
- Dry-run
- 변경 전후 diff
- 가능한 작업에 대한 rollback
